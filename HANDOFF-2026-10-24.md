## The 4.0 GHz clamp (why the power-mode fix exists)

Power saver turns per-policy cpufreq `boost` off and the kernel holds every `scaling_max_freq` at base (4.0 GHz).
Switching back restores the **stored max request**. Normally that's the previous ceiling, but a request written
while boost is off is 4.0 GHz — e.g. OpenFan's *Hardware maximum* pressed in power-saver (reproduced) — and then
"performance" silently runs at base clock until reboot. A reboot in power-saver does **not** cause it (tested).
OpenHW's fix restores each core to its OpenHW cap or the hardware maximum on every boost off→on transition; other
low ceilings are only reported ("Capped at …"). The OpenFan side is written up in openfan-linux
`CPU-BOOST-CLAMP-README.md`.

## Decisions to keep

- **Standalone, and smarter than OpenFan.** Never reference openfan-linux; don't copy its logic blindly either —
  derive behaviour from the hardware's own interfaces (e.g. the PPT range from `power1_cap_max`).
- **Helper commands are fixed and validated**; ranges come from the hardware; writes are read back. Reinstall
  ships in a new .deb that the owner installs. **sudo depends on the running Claude app**: when the claude-desktop
  process has NoNewPrivs=1 (it sets it on itself; seen 2026-10-24, not 2026-10-23), every shell and terminal tab it
  starts inherits it and sudo fails. Check first with `grep NoNewPrivs /proc/$$/status` (1 = blocked); if blocked,
  give the owner the command for a GNOME terminal (Ctrl+Alt+T), which always works.
  Don't run `install-helper.sh` on top of the package: its `/etc` unit would override the packaged one.
- **Boot values live in the owner's existing boot services**, never a new boot path.
- **Menu first**; footer = icon shortcuts. Unimplemented HWiNFO items are shown grayed "To be implemented".
- **Versioning**: semantic, pre-1.0 — bump the **minor** in `Directory.Build.props` for a round of new features, the
  **patch** for fixes only; add a CHANGELOG.md entry and tag `vX.Y.Z` (pushed with `--tags`). Current: **0.6.0**.
- **Every release ships a .deb** (owner, 2026-10-24): after tagging, run `packaging/build-deb.sh` on the tagged
  commit (it refuses a dirty tree; off the tag the version gets `+git.<hash>`). Output in `dist/` (gitignored).
  Then, with the owner's go-ahead, a GitHub release for the tag (CHANGELOG entry + install line as notes, the .deb
  attached). `gh` isn't installed: use the REST API with the token from `/mnt/SOLIDIGM/Claude/.secrets/gh_classic`
  (POST `/repos/russellmm/OpenHW/releases`, then the asset to `uploads.github.com/.../releases/<id>/assets?name=…`
  as `application/vnd.debian.binary-package`). v0.6.0 is released this way (2026-10-24).
- **US spelling on screen** ("Color"). The settings JSON keeps the `Colour` field name so existing files load.
- **Headless testing first**; GUI captures (`import -window <xid>`) for visual changes; never inject desktop input —
  drive the same helper/D-Bus calls instead, and restore whatever a live test changes.

## Gotchas learned the hard way

- **The owner may be using OpenHW while tests run** (a cleared caps file was their click). Ask before calling it a bug.
- **GNOME tray**: no tooltips; each new icon is inserted left of earlier ones (register last-first);
  `LayoutUpdated` rebuilds the menu and closes open submenus — use `ItemsPropertiesUpdated` for changing labels.
- **power-profiles-daemon** announces `ActiveProfile` before it flips boost: wait for boost to match the profile.
- **amd-pstate**: `cpuinfo_max_freq` is 4.0 GHz with boost off; a "hardware maximum" written then stores 4.0 GHz.
- **hsmp-control** refuses boot values outside 100–300 W; the live SMU limit goes to `power1_cap_max`.
- **Helper replies are ASCII** (write "to", not "–").
- **Tmds.DBus.Protocol `MessageWriter` is a ref struct**: pass by ref, never `using var` when passing by ref, and
  don't hold one in an async method. Avalonia 11.2.3 pins Tmds.DBus.Protocol 0.20.0 (NU1903) — upgrade together.
- **Avalonia**: menu gestures are labels only (KeyBindings added separately); `ContextMenu.Opening` fires only via a
  context request (tests raise `ContextRequestedEvent`); disabled items need `ToolTip.ShowOnDisabled`; NumericUpDown
  contains a TextBox; headless captures don't include popups.
- **Per-user install shadows the package**: `~/.local/bin` comes first on PATH and `~/.local/share/applications`
  overrides `/usr/share`, so with both installed, `openhw` and the menu entry run the per-user copy.
- **Commit before `packaging/install-app.sh`**: the footer/About version is `git describe --dirty` at build time, so
  installing with uncommitted edits shows "-dirty" until the next install.
- **OpenHW is Linux-only**, declared once per project (`Platform.cs`).
- **The launcher re-executes itself** once to set `DOTNET_GCgen0size` (`Program.Gen0Budget`): the PID stays the
  same (execve), and `dotnet openhw.dll` doesn't do it.
- **Unix socket paths max out at 108 bytes**: running the tests with `TMPDIR` set to a long path makes
  `ASecondLaunchAsksTheFirstToShow` fail (its socket lands under a temp dir). Not a product bug.
- **Memory measurements are noisy** as single snapshots (GC timing): sample RSS/private every 5 s for 90 s after a
  30 s warm-up, with a copy of the owner's config (`XDG_CONFIG_HOME`), and compare medians.
- **Lingering is enabled for `russellm`**: new group membership needs a reboot. **NTFS mount**: `core.filemode` is
  false — `git update-index --chmod=+x`.
- `/mnt/SOLIDIGM/CLAUDE.md` (website recreation, PowerShell, Windows paths) doesn't apply to this project.
