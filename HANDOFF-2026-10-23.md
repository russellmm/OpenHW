## The 4.0 GHz clamp (why power modes needed fixing)

Power saver turns per-policy cpufreq `boost` off; the kernel then holds every `scaling_max_freq` at base clock
(4.0 GHz). Switching back restores the **stored max request** — normally the previous ceiling, so a plain round
trip is fine (verified with nothing else running). But a request **written while boost is off** is the base clock,
and it survives every later switch: "performance" then silently runs at 4.0 GHz. Reproduced on demand by sending
OpenFan's *Hardware maximum* (`cpufreq all default`) in power-saver. This morning's clamp was either that or the
boot sequence (booted in power-saver) — **unproven; the test is on the roadmap** (power-saver, reboot, switch to
Performance with OpenHW/OpenFan closed, read `scaling_max_freq`).

OpenHW's fix (`PowerModeController`): whenever a profile change turns boost back on, every policy is put back to
**its OpenHW cap, or the hardware maximum**. Caps set through OpenHW are remembered for the current boot in
`~/.config/openhw/cpufreq-caps.json` (keyed by boot id), so a deliberate cap survives power-saver. A ceiling lower
than expected found any other way is only reported ("Capped at …" in footer/tray/Power menu) and fixed on click.
Gotcha found in testing: power-profiles-daemon can announce a profile **before** it flips boost — the controller
waits for boost to match the profile and keeps a sticky "boost was off" flag so no read can race it.

## Decisions to keep

- **Standalone.** OpenHW never references openfan-linux at build or run time. **Don't copy OpenFan's logic
  blindly either** (owner, 2026-10-23): derive limits from the hardware's own interfaces (e.g. the CPU PPT range
  from `power1_cap_max`, not OpenFan's fixed 100–300 W, which can't reach the 9970X's stock 350 W).
- **Helper commands are fixed and validated**: no client input becomes a path or opcode; values are range-checked
  against what the hardware reports; every write is read back. Reinstalling needs the owner's sudo.
- **Menu first** for new features; footer = icon shortcuts only. Settings will be a menu entry.
- **Power limits and caps are live until reboot**; the owner's boot services (`nvidia-power-limit.service`,
  `hsmp-control-apply.service` with `/etc/hsmp-control/ppt_mw`) own boot values. Persistence, if added, should
  edit their config rather than add a third boot path.
- **Headless testing first** (`dotnet test`, `--dump`, headless Skia renders). GUI captures with
  `import -window <xid>` only for visual changes. Don't inject input into the desktop — when a click is needed,
  ask the owner or drive the same helper command directly.
- **Engines per sensor suite**; collapsed groups cost nothing; gray means stale.

## Gotchas learned the hard way

- **The owner may be using OpenHW while tests run.** A cleared caps file mid-test was the owner clicking
  *Remove all caps*. Ask before assuming a bug.
- **power-profiles-daemon** announces `ActiveProfile` before applying boost; wait for boost to match.
- **amd-pstate**: `cpuinfo_max_freq` is 4.0 GHz while boost is off and 5.49 GHz with it on; a *hardware maximum*
  written in power-saver is therefore 4.0 GHz.
- **Helper replies are ASCII**: no "–" in error messages (write "to").
- **`Tmds.DBus.Protocol` `MessageWriter` is a `ref struct`**: take it by ref; you can't hold one in an async
  method — build the message synchronously and return the pending `Task`.
- **Avalonia 11.2.3 pins Tmds.DBus.Protocol 0.20.0** (NU1903 advisory). Upgrade together.
- **Avalonia menu gestures are labels only**; `MainWindow.BuildMenu` adds matching `KeyBindings`.
- **NumericUpDown contains a TextBox** — count editors by watermark in UI tests.
- **Lingering is enabled for `russellm`**: new group membership needs a reboot (`sg openhw -c …` to test sooner).
- **NTFS mount**: git `core.filemode` is false — `git update-index --chmod=+x` for scripts.
- **Expensive reads**: NVML PCIe throughput (~42 ms/GPU, every 10 s) and NVMe hwmon temps (5–19 ms/drive).
- `/mnt/SOLIDIGM/CLAUDE.md` (website recreation, PowerShell, Windows paths) doesn't apply to this project.
